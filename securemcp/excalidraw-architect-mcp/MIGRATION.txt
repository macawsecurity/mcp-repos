MIGRATION: excalidraw-architect-mcp, FastMCP -> SecureMCP
Upstream base: BV-Venky/excalidraw-architect-mcp @ v0.2.3

WHAT
- src/excalidraw_mcp/server.py only. Every other file is identical to upstream.
- "from fastmcp import FastMCP" replaced by SecureMCP.
- Name "Excalidraw Architect" -> "excalidraw-architect": the name is used in
  the agent id.
- @mcp.tool -> @mcp.tool() on the 4 tools (SecureMCP needs the call form).
- 3 tool parameters given a plain type (list): create_diagram.nodes,
  create_diagram.connections, modify_diagram.operations.
- No tool body changed.

WHY
SecureMCP publishes six parameter types: str, int, float, bool, dict, list.
Other annotations (Optional[...], List[...], unions, models) are published as
"string", so each tool parameter gets a plain type. Only the annotation
changes; the original is kept in a "# was:" comment.

DIFFERENCES FROM UPSTREAM
- Constructor argument instructions=... (SecureMCP has no such argument).
- Argument checking. FastMCP validated and converted every argument before the
  tool ran; SecureMCP passes arguments as sent. Arguments are checked by the
  MAPL policy.
- Per-parameter schema detail (descriptions, item types, allowed values) is not
  published. The tool docstring carries it.

NOTES
- The policy limits file paths to relative ".excalidraw" files without "..".

VERIFICATION
- Compared with the upstream base function by function: no tool body differs.
- Served through MACAW and called as a normal MCP client: create_diagram,
  get_diagram_info and modify_diagram returned correct results.

LINES CHANGED
1 Python file, 44 lines differ from upstream.
